# PolyGP 面板改进说明

## 当前项目

`control.py` 管理 VPN 状态、会话和设置，`gp_saml_login.py` 驱动学校登录流程；noVNC 显示容器中的登录浏览器。日常使用的主要任务是发起登录、完成当前认证步骤、查看连接、复制代理地址，以及处理连接中断。

原界面在连接成功后仍显示六步流程、禁用的验证码输入框和服务选择器；设置的保存状态不明显，部分说明还保留了已经取消的“先提交验证码启动登录”操作。这些内容增加了判断当前是否需要操作的负担。

## 本次修改

- 首页按真实状态显示内容。未连接时显示账户摘要和登录按钮；认证中只显示当前步骤；连接后显示代理地址和会话信息。
- 登录进度缩短为登录、验证、连接三步。服务选择在需要时单独出现，验证码只在学校页面要求时接受输入。
- 服务菜单提供选中标记、自动选择说明、浏览器内选择和手动输入入口。服务名称只从选择页面收集，不再被账号或验证码页面的按钮覆盖；列表在服务器端保存，重启后按同一服务器、账号恢复。没有历史选项时会明确说明。
- 代理地址可一键复制。到期时间显示为用户本地时区，同时保留剩余时间。
- 设置的账号、连接、运行信息采用一致的可折叠卡片：标题、说明、控件高度与左右列对齐方式统一，手机宽度下使用上下排列。常用项默认展开，高级配置和运行详情折叠。未保存内容在各页面间同步，状态轮询不会覆盖输入；保存失败保留内容，成功后清除修改标记。
- HIP identity 提供四个设备标识的查看、编辑、JSON/配置文件导入、JSON 导出和随机生成。导入与生成先产生草稿，独立保存到持久卷；当前会话及其恢复保留原标识，新登录采用新值。详见 [HIP 标识管理说明](hip-identity.md)。
- 请求发出后立即禁用相关按钮，防止重复提交。错误提示持续显示；服务暂时不可用时自动重试，并提供手动检查按钮。
- 断开连接、重新登录和重载配置会先说明影响。取消正在进行的登录保持直接操作。
- 表单增加对应标签、键盘操作、焦点提示和验证码错误提示。窄屏使用单列内容，不需要横向拖动登录步骤。
- 前端移到独立 `panel.html`，服务每次读取模板。预览与容器使用同一文件，之后的界面更新可以避免重启 VPN。

## 后续优先方向

### 1. 让设置的保存期限更明确

目前网页设置保存在容器进程中，永久修改仍要编辑 `.env`。可以增加“仅本次运行”和“保存为默认值”的明确选择，配合独立的私有配置文件；不要让只读挂载的 `.env` 承担网页写入。密码继续保持只写入、不在状态接口中返回。

### 2. 根据错误原因提供下一步

目前首页能报告失败，但连接错误仍主要是一段服务端文字。可以将登录超时、验证码拒绝、服务选择不匹配、网络暂时中断分开，并分别提供“重新登录”“输入新验证码”“选择服务”“等待重连”等操作。先覆盖实际最常见的几类错误即可。

### 3. 进一步减少浏览器与首页之间的切换

当前 Browser 提供返回当前步骤的入口。后续可以在需要人工操作时将登录浏览器直接展开在当前步骤下面；完成认证后自动收起。移动端继续保留独立浏览器入口，避免缩得太小而难以输入。

### 4. 区分当前会话和下次登录配置

当前状态接口中的服务名来自可修改的设置。后续可记录建立会话时实际使用的服务器、服务和首次连接时间，避免改设置后，连接卡片看起来像已经切换了服务；重连时也能保留准确的累计连接时间。

这些方向可以按使用反馈逐项实施，优先减少常见操作中的等待和不确定感。
